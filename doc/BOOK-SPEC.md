# 《Blender 开发指南》书稿规格

本文档定义本书的定位、内容边界、结构和验收标准。它用于约束后续写作与审校，不是
一次性生成提示词，也不包含具体机器上的构建记录。构建书稿见
[README-BOOK.md](README-BOOK.md)，准备 Blender 实证环境见
[README-BLENDER.md](README-BLENDER.md)。

## 一、定位与目标读者

《Blender 开发指南》是一本正式、系统的中文技术书，帮助读者完成从“会调用 API”到
“能阅读、修改并验证 Blender 源码”的进阶。

目标读者应具备以下基础：

- 能使用 Python 编写函数、类和模块；
- 能阅读基础 C/C++，理解类、模板、容器和编译过程；
- 知道 Git、CMake 和命令行工具的基本用途；
- 不要求读过 Blender 源码，也不默认熟悉 Blender 内部术语。

全书覆盖三条逐步加深的实践路径：

1. 使用 Python API 开发 addon；
2. 由 Python addon 调用 C ABI 动态库完成原生加速；
3. 修改 Blender C/C++ 源码并参与上游开发。

本书既要能够顺序阅读，也要能够按术语、路径和命令快速查阅。内容不能退化为 API 清单、
命令合集或缺少原理解释的操作手册。

## 二、内容边界

正文必须清楚区分不同扩展方式的能力边界：

- addon 使用 Python 开发；Blender 没有稳定的通用 C++ 插件 ABI；
- Python 可以调用由 C、C++ 或 Rust 等语言实现的原生动态库，但这不等于 Blender 原生
  支持这些语言作为 addon 脚本语言；
- 注册全新的编辑器类型、修改核心数据结构或改变底层求值行为，需要修改 Blender 源码；
- 只有路径、函数名或代码能够查到还不够，正文对行为与设计目的的解释也必须经过源码
  阅读或运行验证。

当前技术内容基于 Blender 5.2 LTS。精确版本、分支、标签和提交号只由
`book/blender-baseline.json` 定义；README 和项目文档不得复制具体提交号。书稿中的兼容性
示例可以保留旧版本信息，不能在升级基准时机械替换。

## 三、交付物

工程内维护以下内容：

- 可编译的 Typst 书稿、公共样式和矢量图定义；
- 真实 Blender 界面截图和必要的静态资源；
- 可独立运行、编译或安装的完整示例源码；
- 用于准备环境、构建书籍和执行质量检查的脚本。

默认书籍产物是 PDF。实验性 HTML 只作为开发预览，不替代正式 PDF。对外发布目录的顶层
只能包含 PDF 和 `examples/`；字体、书稿源码、检查日志和中间构建文件不进入发布包。

正文使用中文，代码、命令、路径和专有术语保留必要的英文。界面截图不超过
1920×1080；优先截取与讲解直接相关的窗口、面板或菜单，避免整屏截图导致界面字体过小。

## 四、全书结构

全书分为三个部分和六个附录。章节主题如下。

### 第 0 篇：基础与准备

- **第 0 章 导论**：本书定位、学习路线、开发边界和写作约定。
- **第 1 章 Blender 架构总览**：源码布局、DNA/RNA、核心子系统、渲染管线和端到端
  数据流。
- **第 2 章 不同平台的开发环境与构建**：通用工具链、源码与依赖、Windows、macOS、
  Linux 的构建流程，以及运行与调试。

### 第 1 篇：Python 插件开发

- **第 3 章 bpy API 全景**：模块地图、数据访问、上下文和 RNA 到 Python 的绑定关系。
- **第 4 章 Addon 结构与生命周期**：注册、卸载、偏好设置、多文件组织和分发。
- **第 5 章 用 Python 定义 UI 与交互**：操作符、面板、属性、事件、快捷键和撤销。
- **第 6 章 数据操作与性能**：网格和 BMesh、批量数据、性能分析及原生库加速。
- **第 7 章 综合案例：完整 Addon 项目**：从需求、结构和实现到测试、打包与发布。

### 第 2 篇：基于源码进行修改

- **第 8 章 源码结构深度导览**：模块前缀、代码风格和源码定位方法。
- **第 9 章 数据层：DNA 与 RNA**：SDNA、序列化、版本迁移、RNA 和代码生成。
- **第 10 章 基础库 BLI 与 C++ 约定**：内存、容器、数学、路径、日志和错误处理。
- **第 11 章 操作符、事件与窗口系统**：事件分发、操作符、通知、撤销及 bpy 映射。
- **第 12 章 编辑器与 UI**：SpaceType、区域、布局、GPU 抽象和编辑器扩展。
- **第 13 章 依赖图与求值**：关系图、copy-on-evaluation、脏标记和并行求值。
- **第 14 章 修饰器、节点与几何处理**：修饰器体系、节点注册和几何数据处理。
- **第 15 章 渲染管线与引擎**：渲染框架、Cycles、EEVEE、合成和 RenderEngine。
- **第 16 章 调试、性能与优化**：调试器、日志、profiling、内存和并行。
- **第 17 章 测试与上游贡献**：测试体系、代码规范、评审流程和贡献路径。

### 附录

- **附录 A 术语表**；
- **附录 B 源码路径索引**；
- **附录 C Blender 构建与开发命令速查**；
- **附录 D 不同平台的构建差异对照表**；
- **附录 E Blender 构建与开发排错**；
- **附录 F 图表索引**。

章节可以随内容演进调整小节，但不得破坏“建立整体模型 → 学会插件开发 → 进入源码开发”
这条学习主线。

## 五、重点概念的展开要求

以下主题不能只给定义或列出 API。应按“解决什么问题 → 为什么这样设计 → 源码在哪里 →
如何使用或修改 → 常见失败方式”的顺序展开：

1. DNA、SDNA、RNA 与代码生成；
2. ID、Main、`.blend` 序列化和版本迁移；
3. 依赖图与 copy-on-evaluation；
4. 操作符、事件、通知、撤销和界面刷新；
5. SpaceType、ScrArea、ARegion 与 PanelType；
6. GPU 抽象和 draw manager；
7. 渲染、求值、合成与输出管线；
8. bpy 的自动生成机制与 Python/C++ 边界；
9. guardedalloc、所有权与 BLI 容器选择；
10. 修饰器、节点和几何数据处理。

前文若必须提前使用后文才完整解释的概念，应给出简短上下文和交叉引用。不会影响当前
推理的术语别名、命名来历或轻量背景可以放入脚注；操作前提、版本差异、安全警告和核心
证据必须留在正文。

## 六、构建内容的范围

第 2 章与构建附录应覆盖 Windows、macOS 和 Linux，但不应把平台差异写成三套彼此割裂的
教程。先讲共同的 CMake 工程、依赖模型和构建阶段，再按平台说明入口、编译器、产物和
调试器的差异。

构建内容需要满足以下要求：

- Windows 以 MSVC 和 Visual Studio 工具链为准，不把 MSYS2、MinGW 或 clang-cl 写成
  本书验证过的默认路径；
- macOS 说明 Xcode Command Line Tools、Apple Clang 和应用包产物；
- Linux 说明发行版开发包、GCC/Clang、Ninja/Makefiles 和可选依赖自编译；
- CMake 只讲读者完成 Blender 构建实际需要的目标、生成器、缓存、构建目录和配置类型；
- 预编译库和 Git LFS 的说明必须以当前基准源码中的 `.gitmodules`、更新脚本和
  `CMakeLists.txt` 为依据，不照搬旧版 SVN 流程；
- 镜像只作为网络不稳定时的补充说明，不能取代官方流程或把临时镜像状态写进正文主线。

## 七、证据与版本规则

涉及技术事实时必须形成可复查的证据链：

1. 在基准源码中定位实现、声明或构建逻辑；
2. 使用 `#src(...)` 标注需要精确核对的路径和行号；
3. 对行为相关结论执行最小可运行测试；
4. 对构建、性能和界面结论保留可复现条件；
5. 写入正文后运行源码引用检查和完整书稿检查。

关键示例应真实运行或编译。为了讲解而省略代码时必须明确标注“节选”或“示意”；不能把
未验证的伪代码包装成完整实现。性能数字只能来自可复现测量，不能用主观感受代替。

书稿正文不得提及本书工程内部的默认源码目录、检查脚本或仓库组织。读者看到的命令和路径
必须能够在独立的 Blender 源码检出中成立。工程维护细节只写在 README 与 `doc/` 中。

## 八、写作与排版规则

- 中文表达应直接、克制，避免模板化口号、空泛总结和为了强调而滥用绝对化词语。
- 术语首次出现时加粗并附英文；之后保持中文名称和英文拼写一致。
- 代码块标明语言，长行按语言惯例主动换行并对齐，不依赖 PDF 强制折行。
- 图表、章节和附录编号由 Typst 自动生成，正文使用标签交叉引用，不手写编号。
- 路径、函数名、类型名和命令使用行内代码；长路径必须允许在分隔符后断行。
- 表格优先精简内容和调整列宽，只有必要时才使用更小字号。
- 外部网址同时提供可点击链接和可供纸质阅读输入的明文地址。
- 完整示例放在 `book/examples/`，正文只保留与当前讲解直接相关的片段，并用脚注标明
  发布包中的相对路径。

具体 Typst 写法、字体和视觉规则见 [README-BOOK.md](README-BOOK.md)。

3. 不同平台的构建流程；
4. DNA → SDNA → RNA → bpy 代码生成管线；
5. ID、Main 与数据块关系；
6. 事件 → 操作符 → 执行 → 通知 → 撤销链路；
7. SpaceType、ScrArea 与 ARegion 层级；
8. 依赖图节点、关系与求值过程；
9. 场景 → 求值 → 引擎 → 合成 → 输出的渲染管线；
10. Python addon 生命周期；
11. Python/C++ 分工与是否下沉原生代码的决策路径。

图表必须帮助理解结构或流程，不能只是把段落换成方框。图中类型、函数、路径和箭头方向
同样属于技术事实，必须核对源码并进行视觉检查。
